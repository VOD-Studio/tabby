托管模式下，这三项都可在「设置」管理。TUN 开关位于「TUN → 启用」，登录启动和系统代理位于「托管内核」。

## TUN

启用前，先关闭其他内核的 TUN 自动路由。托管内核首次开启 TUN 时会弹出授权确认。

| 平台 | 授权方式和限制 |
| --- | --- |
| Linux | 通过 `pkexec` 或 `sudo setcap` 赋予内核所需能力，Tabby 本身继续以普通用户运行。`nosuid` 挂载会阻止这种授权。 |
| macOS | Tabby 请求管理员授权，将内核设为 root 所有并设置 setuid。这样任何能执行该文件的本机用户都可以以 root 权限运行它。仅在个人独用设备上考虑启用。`nosuid` 或无所有权的挂载可能阻止该方式。 |

升级内核后需要重新授权。若授权失败，检查内核文件所在的文件系统和界面提示。需要回到普通代理方式时，关闭 TUN 后改用应用代理设置或系统代理。

## 登录启动

「登录时启动」为内核设置随用户登录运行。Linux 使用 systemd 用户管理器，macOS 使用当前用户的 LaunchAgent。缺少可用的用户管理器时，设置页会显示此项不可用。

关闭该选项会移除自动启动配置。若还需停止正在运行的内核，请再选择「停止内核」。

## 系统代理

Linux 支持 GNOME、MATE、Cinnamon 和 KDE，macOS 通过网络服务配置。打开「系统代理」会把系统代理指向托管内核的本地 Mixed 端口。关闭系统代理或由 Tabby 停止内核时，会尝试恢复原值。

内核被外部进程停止时，系统代理可能仍保留。此时在 Tabby 设置里关闭该开关，并在系统网络设置中核对恢复结果。

:::note[验证范围]
尚未实机验证的项目包括 TUN 授权与路由、桌面代理，以及注销后重新登录时的内核自启。macOS 的集成逻辑由单元测试覆盖。
:::
