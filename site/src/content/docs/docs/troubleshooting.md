## 提示控制器不可达

1. 确认内核正在运行，控制器地址与实际监听地址一致。常用控制器端口是 `9090`，常用 Mixed 端口 `7890` 负责承载代理流量。
2. 检查协议 `http://` 或 `https://`，以及远程内网或端口转发是否可达。
3. 校正配置后在 Tabby 按 `r` 重试，或按 `P` 切换控制器。

可用 `curl --noproxy '*' -i http://127.0.0.1:9090/version` 检查本机控制器，并按实际地址调整。返回内核版本表示可以访问，返回 `401` 表示已收到控制器响应，还需提供密钥。连接控制器时 Tabby 会忽略 HTTP 代理环境变量。

## 提示未授权或密钥错误

核对 mihomo 配置的 `secret`，以及 `TABBY_SECRET` 或所选 `[profiles]` 的密钥。检查 shell 环境和启动命令，显式参数或环境变量会覆盖文件。详见[参数优先级](../reference/configuration/#命令行和环境变量)。

## 托管内核无法启动或端口被占用

- 查看启动失败页给出的原因，也可在[启动日志](#去哪里看日志)中查找端口或配置错误。
- 确认旧代理客户端与 Tabby 使用不同的 Mixed 端口。可在设置页调整端口，随后更新引用旧端口的应用。
- 新配置启动失败时，先用已知可用的订阅检查，再检查发生错误的订阅和最近的 DNS 或 TUN 改动。

## 代理可连接，应用还是无法访问

先用[托管快速开始](../quick-start/managed/#3-导入并切换订阅)里的 `curl --proxy` 方法验证应用入口。到[连接页](../use/connections/)核对命中规则和链路。测速全失败时，另选一个这些节点可访问的[测速地址](../reference/configuration/#测速参数)再试。

## 订阅导入或更新失败

检查源文件是否仍在原路径，或 URL 是否已过期。确认订阅下载路线能访问源地址，age 加密订阅的 X25519 私钥与该订阅匹配。更新失败时先保留现有订阅，按[订阅管理](../manage/subscriptions/)逐项排查。

## 去哪里看日志

- **Tabby 应用日志**位于状态目录的 `tabby.log`。临时使用 `RUST_LOG=tabby=debug tabby` 收集更多诊断信息。
- **内核日志页**在 Tabby 按 `6` 打开，用来查看内核推送的实时消息。
- **托管内核进程日志**在 Linux 的 systemd 用户模式下写入 journal。查找数据目录下 `core/state.toml` 的 `unit` 字段，然后运行 `journalctl --user -u <单元名>`。macOS launchd 和独立进程模式将日志写入数据目录下的 `core/core.log`。

路径和平台差异见[文件位置](../reference/configuration/#文件位置)。反馈时附上版本、系统和已脱敏的报错片段。
